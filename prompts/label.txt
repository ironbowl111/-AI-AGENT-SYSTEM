# 【プロンプト②】step ごとの観点ラベル付け（研究計画 第 4 節）
# 置換変数: {probes}, {step}, {sop_text}, {previous}
あなたは認知タスク分析の分析者です。以下の作業ステップについて、8 つの観点それぞれに「熟練者に問う価値がどれだけあるか」を 0〜2 で評価してください。

## 観点の定義（この定義以外の解釈をしないこと）
{probes}

## 採点の意味
- 2: この観点に、手順書に書かれていない知識が存在する可能性が高い
- 1: 可能性はあるが確実ではない
- 0: この観点で問うべきことは無さそう

## 採点の規則（必ず守ること）
- 8 観点のうち、2 を付けられるのは最大 2 観点、1 は最大 3 観点、残りは 0 にする。
  すべてに 1 以上を付けることは禁止。
- 2 を付ける観点は「この工程の action に書かれた語句」を根拠にできるものに限る。
  根拠にした語句を reason に引用すること。
- action に書かれていないこと、作業一般の常識（例：ねじ作業なら角度の判断がある）を根拠にしない。
  action が短く手がかりがない場合は、全観点 0 でよい。
- 対応する SOP の記述がある場合、SOP と action の差（SOP にない動作、順序や方法の違い）を
  2 の根拠にしてよい。

## 対象ステップ
{step}

## 対応する SOP の記述
{sop_text}

## 前サイクルの結果
{previous}
前サイクルの結果がある場合、ゼロから付け直さないでください。実際の対話結果と食い違った観点だけを調整します。
- 高く付けたのに何も引き出せなかった観点 → 下げる
- 低く付けたのに自発的発話で出てきた観点 → 上げる

## 出力
JSON のみ。全 8 観点について labels と reason を埋める。
下記はキーの形を示すためのもので、値はすべてプレースホルダーである。
`<...>` をそのまま出力してはならない。必ずこの工程の内容で埋めること。
{{
  "labels": {{"<probe_key>": <0|1|2>, ...}},
  "reason": {{"<probe_key>": "<action から引用した語句と、それがこの観点の知識を示唆する理由を 1 文。0 の場合は「手がかりなし」>", ...}}
}}
